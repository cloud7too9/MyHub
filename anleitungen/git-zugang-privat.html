Zugang zu privaten Repositories einrichten

⏱ ca. 15 Min Aktualisiert 04.08.2026 GitHub · VS Code

Drei Wege, sich gegenüber GitHub auszuweisen — einmal pro Rechner eingerichtet, danach läuft Klonen und Pushen ohne Nachfragen.

1
Einmalig pro Rechner

Weg wählen — nur einer ist nötig

  • A · Browser-Login in VS Code — der einfachste Weg auf dem eigenen Rechner, keine Verwaltung nötig.
  • B · Personal Access Token (PAT) — wenn der Browser-Login nicht greift oder eine Gitea-/GitLab-Instanz im Spiel ist.
  • C · SSH-Schlüssel — auf Dauer der angenehmste: kein Passwort, kein Token-Ablauf.
Empfehlung
Eigener Hauptrechner: A für den schnellen Start, C für die Dauer. Für den SSD-Workflow an fremden Rechnern gibt es die eigene Anleitung Git von der portablen SSD nutzen.
2
Einmalig pro Rechner

Weg A: Browser-Login in VS Code

Beim ersten Klonen oder Pushen eines privaten Repos öffnet VS Code automatisch den Browser → bei GitHub anmelden → Zugriff bestätigen. Fertig.

Vorab geht es auch: Zahnrad unten links → Konten → Bei GitHub anmelden.

Ergebnis
Die Zugangsdaten liegen im Anmeldeinformations­manager des Systems (unter Windows: Anmeldeinformationsverwaltung) — keine erneute Anmeldung nötig. Sie hängen damit an diesem Rechner, nicht am Projekt.
3
Einmalig pro Rechner

Weg B: Personal Access Token

GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → neues Token:

  • Zugriff nur auf die benötigten Repos einschränken
  • Berechtigung Contents: Read and write
  • Ablaufdatum setzen — lieber kurz und bei Bedarf verlängern

Fragt Git beim Klonen oder Pushen nach dem Passwort, kommt das Token statt des Passworts hinein.

Wie ein Passwort behandeln
Das Token wird nach dem Erstellen genau einmal angezeigt. Nirgendwo in Dateien oder Repos ablegen — wer es hat, hat den Repo-Zugriff.
4
Einmalig pro Rechner

Weg C: SSH-Schlüssel

Terminal
# Schlüsselpaar erzeugen (Passphrase empfohlen)
ssh-keygen -t ed25519 -C "max@example.de"

# Öffentlichen Schlüssel anzeigen und kopieren
cat ~/.ssh/id_ed25519.pub

Den öffentlichen Schlüssel bei GitHub unter Settings → SSH and GPG keys → New SSH key hinterlegen. Repos danach per SSH-URL klonen:

Terminal
git clone git@github.com:benutzer/repo.git
Bestehendes Repo umstellen
Ein per HTTPS geklontes Repo wechselt mit git remote set-url origin git@github.com:benutzer/repo.git auf SSH — ohne neu zu klonen.
Schlüssel schon vorhanden?
Wer VS Code mit dem Hetzner-Server verbinden durchlaufen hat, besitzt ~/.ssh/id_ed25519 bereits — derselbe Schlüssel dient dort als Server-Zugang. Dann hier nichts neu erzeugen, nur den öffentlichen Teil zusätzlich bei GitHub hinterlegen.
5
Einmalig pro Rechner

Zugang testen

Terminal — bei Weg C
# Muss mit "Hi <benutzer>!" antworten
ssh -T git@github.com

Bei Weg A und B genügt der Praxistest: ein privates Repo klonen oder einen kleinen Commit pushen — läuft es ohne Nachfrage durch, sitzt der Zugang.

Abschluss-Checkliste

Weg gewählt (A, B oder C)
