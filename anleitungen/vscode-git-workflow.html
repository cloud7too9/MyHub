Repo in VS Code klonen & Änderungen hochladen

⏱ ca. 10 Min Aktualisiert 04.08.2026 VS Code · GitHub

Der Alltagsablauf: Repo holen, bearbeiten, sauber committen, synchronisieren — jeweils per Oberfläche und als Terminal-Äquivalent.

Das einmalige Klonen ist ausgeblendet — sichtbar bleibt der Ablauf bei jeder Arbeitssitzung.

1
Einmalig pro Repo

Repository klonen

In VS Code: Strg+Umschalt+P → „Git: Clone" → Repo-URL einfügen (auf GitHub: grüner Code-Button → HTTPS- oder SSH-URL kopieren) → Zielordner wählen → Nachfrage „Projekt öffnen?" bestätigen.

Terminal-Äquivalent (Strg+ö)
git clone https://github.com/benutzer/repo.git
cd repo
code .
Privates Repo?
Dann fragt Git nach einer Anmeldung — die drei Wege stehen in Zugang zu privaten Repositories einrichten.
2
Bei jeder Sitzung

Vor der Arbeit: aktuellen Stand holen

Erste Handlung jeder Sitzung — vor der ersten Änderung. In VS Code: Sync-Symbol unten links in der Statusleiste.

Terminal-Äquivalent
git pull
Mehrere Rechner
Wer an mehreren Geräten arbeitet und diesen Schritt auslässt, produziert beim Push Konflikte. Pull zuerst ist die billigste Versicherung.
3
Bei jeder Sitzung

Änderungen prüfen und stagen

Linke Seitenleiste → Quellcodeverwaltung (Strg+Umschalt+G). Jede geänderte Datei anklicken und den Diff überfliegen — erst dann mit + stagen (einzeln, oder das + an „Änderungen" für alle).

Terminal-Äquivalent
# Überblick, dann alles stagen
git status
git add .
Der Diff-Blick lohnt
Der kurze Blick vor dem Stagen fängt vergessene Debug-Zeilen und versehentlich geänderte Dateien ab — und verhindert, dass eine .env ins Repo rutscht.
4
Bei jeder Sitzung

Committen

Nachricht ins Textfeld oben, dann Strg+Eingabe.

Terminal-Äquivalent
git commit -m "Auftragsmodell überarbeitet"
Klein und thematisch
Ein Commit = eine abgeschlossene Änderung. Kein Sammel-Commit am Tagesende — kleine Commits lassen sich einzeln zurücknehmen und im Verlauf verstehen.
5
Bei jeder Sitzung

Synchronisieren (hochladen)

Button „Änderungen synchronisieren" in der Quellcodeverwaltung — führt Pull und Push in einem Schritt aus.

Terminal-Äquivalent
git pull --rebase
git push
Ergebnis
Der Stand liegt auf GitHub — kontrollierbar im Repo unter Commits. Läuft ein Deploy per Action, startet er jetzt automatisch.

Abschluss-Checkliste

0 / 4
Repo geklont und in VS Code geöffnet
Sitzung mit Pull begonnen
Diffs vor dem Stagen geprüft
Thematisch committet und synchronisiert
