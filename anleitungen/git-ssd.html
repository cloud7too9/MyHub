Git von der portablen SSD nutzen

⏱ ca. 20 Min Aktualisiert 04.08.2026 SSD · fremde Rechner

Zugangsdaten aus Browser-Login und Token hängen am jeweiligen Rechner — nicht an der SSD. Die Lösung: ein eigener SSH-Schlüssel samt Konfiguration reist auf der SSD mit, und Git wird am fremden Rechner nur kurz darauf gezeigt.

Die einmalige Einrichtung der SSD ist ausgeblendet — sichtbar bleibt der Ablauf an jedem fremden Rechner.

1
Einmalig auf der SSD

Eigenen Schlüssel für die SSD erzeugen

Ein separater Schlüssel nur für unterwegs — nicht der Hauptschlüssel deines Rechners. Geht die SSD verloren, ziehst du bei GitHub nur diesen einen zurück.

Terminal
# Ordner auf der SSD anlegen und Schlüssel direkt dorthin
mkdir -p /pfad/zur/ssd/.portable-ssh
ssh-keygen -t ed25519 -C "ssd-portable" -f /pfad/zur/ssd/.portable-ssh/id_ed25519
Passphrase ist hier Pflicht
Anders als beim Server-Deploy-Key: Dieser Schlüssel liegt auf einem Datenträger, der verloren gehen kann. Die Passphrase ist die letzte Verteidigungslinie — ohne sie ist die gefundene SSD ein GitHub-Generalschlüssel.
2
Einmalig auf der SSD

Öffentlichen Schlüssel bei GitHub hinterlegen

Terminal
cat /pfad/zur/ssd/.portable-ssh/id_ed25519.pub

Inhalt kopieren → GitHub → Settings → SSH and GPG keys → New SSH key → als Titel z. B. „SSD portable" — so ist beim Aufräumen sofort klar, welcher Schlüssel das ist.

3
Einmalig auf der SSD

SSH-Konfiguration auf die SSD legen

Damit du am fremden Rechner nicht mit Pfaden hantierst, bekommt die SSD eine eigene config:

/pfad/zur/ssd/.portable-ssh/config
Host github.com
  User git
  IdentityFile /pfad/zur/ssd/.portable-ssh/id_ed25519
  IdentitiesOnly yes
Pfad ändert sich je Rechner
Laufwerksbuchstabe (Windows) bzw. Einhängepunkt (Linux/macOS) der SSD variieren. Der IdentityFile-Pfad in der config muss dann kurz angepasst werden — oder du nutzt in Schritt 4 die Variante ohne config, die den Pfad direkt mitgibt.
4
An jedem fremden Rechner

Git auf die SSD zeigen lassen

Gilt nur für das aktuelle Terminal-Fenster — nach dem Schließen ist nichts davon übrig. Genau das ist gewollt.

Git Bash / Linux / macOS
export GIT_SSH_COMMAND="ssh -F /pfad/zur/ssd/.portable-ssh/config"
PowerShell
$env:GIT_SSH_COMMAND = 'ssh -F E:\.portable-ssh\config'
Variante ohne config — Pfad direkt mitgeben
export GIT_SSH_COMMAND="ssh -i /pfad/zur/ssd/.portable-ssh/id_ed25519 -o IdentitiesOnly=yes"
Linux/macOS: Rechte-Meldung
Ist die SSD mit exFAT/FAT32 formatiert, kann sie keine Unix-Dateirechte speichern — SSH verweigert dann mit „UNPROTECTED PRIVATE KEY". Abhilfe: Schlüssel für die Sitzung kurz kopieren: cp <ssd>/id_ed25519 /tmp/ && chmod 600 /tmp/id_ed25519 und den Pfad in -i darauf zeigen — hinterher löschen (Schritt 6). Unter Windows tritt das nicht auf.
5
An jedem fremden Rechner

Testen und arbeiten wie gewohnt

Terminal (dasselbe Fenster!)
# Muss mit "Hi <benutzer>!" antworten
ssh -T git@github.com

# Danach normal — SSH-URLs verwenden
git clone git@github.com:benutzer/repo.git
# … bearbeiten, add, commit, pull --rebase, push …
Fenster gewechselt?
Die Variable gilt nur im gesetzten Terminal. Ein neues Fenster oder das VS-Code-Terminal braucht den export aus Schritt 4 erneut. Der Arbeitsablauf selbst steht in Repo in VS Code klonen & Änderungen hochladen.
6
An jedem fremden Rechner

Keine Spuren hinterlassen

  • Alle Änderungen gepusht? Lokale Klone auf dem fremden Rechner löschen — oder direkt auf der SSD arbeiten.
  • Falls der Schlüssel nach /tmp kopiert wurde: rm /tmp/id_ed25519
  • Terminal schließen — damit ist GIT_SSH_COMMAND weg.
  • Falls zwischendurch doch HTTPS mit Anmeldung benutzt wurde: Windows-Anmeldeinformations­verwaltung öffnen und den git:https://github.com-Eintrag entfernen.
Ergebnis
Auf dem fremden Rechner bleibt nichts zurück — Schlüssel und Zugang existieren nur auf der SSD und bei GitHub.
