Arbeitsplatz einrichten

⏱ ca. 90 Min Aktualisiert 13.08.2026 Windows PowerShell 7

Von Null bis arbeitsfähig. Die ersten 14 Schritte gelten einmal pro Rechner und bauen aufeinander auf — die Reihenfolge ist keine Empfehlung. Die letzten 7 fallen bei jedem neuen Projekt erneut an.

Das ⓘ führt weiter
Neben jeder Schritt-Überschrift steht ein Info-Symbol. Es springt in die passende Karte im Werkzeugkasten — dort steht, wozu das Werkzeug gut ist und was es sonst noch kann. Hier steht nur, was jetzt zu tun ist.

Der Aufbau des Rechners ist ausgeblendet — sichtbar bleibt, was bei jedem neuen Projekt erneut anfällt.

Grundgerüst

3 Schritte
Einmalig pro Rechner

Paketverwaltung bereitstellen

winget kommt mit Windows 11. Fehlt es, über den Microsoft Store „App Installer" nachinstallieren.

PowerShell
winget --version
winget upgrade --all
Prüfen
PowerShell
winget --version

Soll: Eine Versionsnummer, z. B. v1.8.x.

Stimmt nicht

Kein Befehl gefunden: Store öffnen, „App Installer" installieren, Terminal neu starten. Danach Scoop als Ergänzung für Werkzeuge ohne Adminrechte:

PowerShell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Invoke-RestMethod -Uri https://get.scoop.sh | Invoke-Expression
Einmalig pro Rechner

Terminal und PowerShell 7

Beides installieren, danach im Terminal unter Einstellungen → Standardprofil auf „PowerShell" umstellen (nicht „Windows PowerShell").

PowerShell
winget install --id Microsoft.WindowsTerminal -e
winget install --id Microsoft.PowerShell -e
Hinweis
Ab hier alle weiteren Schritte im neuen Terminal ausführen, nicht in der alten Konsole.
Prüfen
PowerShell
$PSVersionTable.PSVersion

Soll: Major 7 oder höher.

Stimmt nicht

Steht dort 5.1, läuft noch die alte Shell. Terminal schließen, „PowerShell 7" aus dem Startmenü öffnen und das Standardprofil setzen.

Einmalig pro Rechner

Profil-Datei anlegen

Diese Datei sammelt später alle Aliase und Tastenkürzel. Einmal anlegen, dann in späteren Schritten befüllen.

PowerShell
if (!(Test-Path $PROFILE)) { New-Item -ItemType File -Path $PROFILE -Force }
notepad $PROFILE
Prüfen
PowerShell
Test-Path $PROFILE

Soll: True.

Stimmt nicht

Bei False fehlt der Ordner. Anlegen und erneut versuchen:

PowerShell
New-Item -ItemType Directory -Force -Path (Split-Path $PROFILE)
New-Item -ItemType File -Path $PROFILE -Force

Identität und Zugang

4 Schritte
Einmalig pro Rechner

Git installieren und einrichten

Ohne Identität verweigert Git den ersten Commit. Beide Werte landen dauerhaft in jedem Commit.

PowerShell
winget install --id Git.Git -e
git config --global user.name "Vorname Nachname"
git config --global user.email "mail@beispiel.de"
git config --global init.defaultBranch main
git config --global pull.rebase true
git config --global core.autocrlf true
Prüfen
PowerShell
git config --global --list

Soll: user.name und user.email mit deinen Werten.

Stimmt nicht

Fehlt ein Eintrag, einzeln nachsetzen. Ein Tippfehler in der Mail lässt sich mit demselben Befehl überschreiben:

PowerShell
git config --global user.email "richtige@beispiel.de"
Einmalig pro Rechner

SSH-Schlüssel bereitstellen

Wähle den Weg, der zu deiner Lage passt.

Dateinamen bei der Nachfrage leer lassen — dann finden alle Werkzeuge den Schlüssel automatisch. Passphrase vergeben.

PowerShell
ssh-keygen -t ed25519 -C "max@arbeitsrechner"

Die beiden Dateien id_ed25519 und id_ed25519.pub in den .ssh-Ordner kopieren, danach obigen Befehl für die Rechte ausführen — sonst verweigert OpenSSH den Schlüssel.

PowerShell
New-Item -ItemType Directory -Force -Path $env:USERPROFILE\.ssh
icacls $env:USERPROFILE\.ssh\id_ed25519 /inheritance:r /grant:r "$env:USERNAME:(R)"
Nicht weitergeben
Die Datei ohne .pub ist der private Schlüssel. Sie verlässt den Rechner nie, kommt in kein Repository und wird nicht per Mail oder Chat verschickt.
Prüfen
PowerShell
ssh-keygen -l -f $env:USERPROFILE\.ssh\id_ed25519.pub

Soll: 256 SHA256:… ed25519 — der Fingerabdruck des Schlüssels.

Stimmt nicht

Meldung „No such file": Der Schlüssel liegt nicht am Standardort. Ordnerinhalt anzeigen und Dateien ggf. dorthin verschieben:

PowerShell
dir $env:USERPROFILE\.ssh
Einmalig pro Rechner

GitHub verbinden

Die CLI installieren, anmelden und den öffentlichen Schlüssel hinterlegen. Die Anmeldung richtet gleichzeitig die Git-Zugangsdaten ein.

PowerShell
winget install --id GitHub.cli -e
gh auth login
gh ssh-key add $env:USERPROFILE\.ssh\id_ed25519.pub --title "Arbeitsrechner"
Hinweis
Bei gh auth login: GitHub.com → SSH → vorhandenen Schlüssel wählen → im Browser bestätigen.
Prüfen
PowerShell
gh auth status
ssh -T git@github.com

Soll: Angemeldet als dein Konto, dazu eine Begrüßung von GitHub mit deinem Benutzernamen.

Stimmt nicht

„Permission denied (publickey)": Der Schlüssel ist noch nicht bei GitHub. Vorhandene Schlüssel prüfen und ggf. neu hinzufügen:

PowerShell
gh ssh-key list
Einmalig pro Rechner

Server-Kurznamen anlegen

Nur nötig, wenn ein eigener Server im Spiel ist. Datei ~/.ssh/config anlegen und pro Server einen Block eintragen.

~\.ssh\config
Host mein-server
  HostName 203.0.113.10
  User max
  IdentityFile ~/.ssh/id_ed25519
Hinweis
Danach genügt ssh mein-server statt der vollen Adresse. Öffnen mit: notepad $env:USERPROFILE\.ssh\config
Prüfen
PowerShell
ssh mein-server "echo verbunden"

Soll: Das Wort „verbunden" erscheint.

Stimmt nicht

Datei fehlt oder ist leer? Anlegen und öffnen:

PowerShell
New-Item -ItemType File -Force -Path $env:USERPROFILE\.ssh\config
notepad $env:USERPROFILE\.ssh\config

Laufzeiten

4 Schritte
Einmalig pro Rechner

Node über fnm

Versionsmanager statt fester Installation — sonst blockieren sich Projekte mit unterschiedlichen Node-Versionen gegenseitig.

PowerShell
winget install --id Schniz.fnm -e
fnm install --lts
fnm default lts-latest
Hinweis
Danach diese Zeile ans Ende von $PROFILE hängen, damit fnm beim Verzeichniswechsel automatisch umschaltet: fnm env --use-on-cd --shell powershell | Out-String | Invoke-Expression
Prüfen
PowerShell
node -v
fnm list

Soll: Die LTS-Version, in der Liste als default markiert.

Stimmt nicht

„node wird nicht erkannt": Die Profil-Zeile fehlt oder das Terminal wurde nicht neu gestartet. Profil öffnen, Zeile prüfen, Terminal neu starten:

PowerShell
notepad $PROFILE
Einmalig pro Rechner

pnpm aktivieren

Kommt über Corepack mit Node mit, muss nur eingeschaltet werden.

PowerShell
corepack enable pnpm
Prüfen
PowerShell
pnpm -v

Soll: Versionsnummer ohne Fehler.

Stimmt nicht

Fehler bei corepack: Node-Version zu alt oder fnm-Zeile fehlt. Node prüfen, danach erneut aktivieren:

PowerShell
node -v
corepack enable pnpm
Einmalig pro Rechner

Python über uv

Nur nötig, wenn Python-Projekte anstehen. uv bringt Versionen, virtuelle Umgebungen und Pakete in einem Werkzeug mit.

PowerShell
winget install --id astral-sh.uv -e
uv python install 3.12
Prüfen
PowerShell
uv --version
uv python list

Soll: Version plus Liste mit 3.12.

Stimmt nicht

Ist bereits ein System-Python installiert, stört das nicht — uv verwaltet seine eigenen Versionen getrennt davon.

Einmalig pro Rechner

Docker bereitstellen

WSL2 muss zuerst stehen. Nach der Docker-Installation einmal ab- und wieder anmelden.

PowerShell
wsl --install
winget install --id Docker.DockerDesktop -e
Hinweis
Der wsl-Befehl verlangt in der Regel einen Neustart. Danach mit dem zweiten Befehl weitermachen.
Prüfen
PowerShell
docker run --rm hello-world

Soll: Die Begrüßungsmeldung des Testcontainers.

Stimmt nicht

„Cannot connect to the Docker daemon": Docker Desktop läuft nicht. Starten, warten bis das Symbol grün ist, dann erneut prüfen. Bei WSL-Fehlern:

PowerShell
wsl --update
wsl --status

Werkzeuge und Editor

3 Schritte
Einmalig pro Rechner

VS Code einrichten

Wähle, wie die Einstellungen auf den Rechner kommen.

Nach dem Start: Zahnrad unten links → „Einstellungen synchronisieren aktivieren" → mit GitHub anmelden. Erweiterungen, Tastenkürzel und Theme kommen automatisch mit. Empfohlener Weg bei einem Zweitrechner.

PowerShell
winget install --id Microsoft.VisualStudioCode -e

Danach in den Einstellungen „Format On Save" aktivieren und Prettier als Standardformatierer setzen.

PowerShell
winget install --id Microsoft.VisualStudioCode -e
code --install-extension EditorConfig.EditorConfig
code --install-extension esbenp.prettier-vscode
code --install-extension dbaeumer.vscode-eslint
Prüfen
PowerShell
code --version

Soll: Version, Commit-Hash und Architektur.

Stimmt nicht

„code wird nicht erkannt": Der PATH-Eintrag fehlt. In VS Code die Befehlspalette öffnen (Ctrl+Shift+P) und „Shell Command: Install code command in PATH" ausführen, danach Terminal neu starten.

Einmalig pro Rechner

Kommandozeilen-Helfer installieren

Sechs kleine Werkzeuge in einem Rutsch — Suche, Auswahl, JSON, Anzeige, Aufgaben.

PowerShell
winget install --id BurntSushi.ripgrep.MSVC -e
winget install --id junegunn.fzf -e
winget install --id jqlang.jq -e
winget install --id sharkdp.bat -e
winget install --id eza-community.eza -e
winget install --id Casey.Just -e
Prüfen
PowerShell
rg --version; fzf --version; jq --version; bat --version; eza --version; just --version

Soll: Sechs Versionszeilen ohne Fehler dazwischen.

Stimmt nicht

Meldet eines der Werkzeuge nichts, fehlt der PATH-Eintrag im laufenden Terminal. Terminal neu starten und erneut prüfen. Hilft das nicht, einzeln nachinstallieren:

PowerShell
winget install --id BurntSushi.ripgrep.MSVC -e --force
Einmalig pro Rechner

Profil-Datei abschließen

Jetzt alles in $PROFILE zusammenführen: Tastenkürzel und Aliase. Öffnen mit notepad $PROFILE.

PowerShell
Install-Module PSFzf -Scope CurrentUser -Force
$PROFILE — ans Ende anhängen
fnm env --use-on-cd --shell powershell | Out-String | Invoke-Expression
Import-Module PSFzf
Set-PsFzfOption -PSReadlineChordProvider "Ctrl+t" -PSReadlineChordReverseHistory "Ctrl+r"
Set-Alias -Name ll -Value eza
function lg { eza -l --git --icons }
Hinweis
Danach Terminal neu starten. Ctrl+R durchsucht ab jetzt den Befehlsverlauf, Ctrl+T die Dateien im aktuellen Ordner.
Prüfen
PowerShell
Get-Content $PROFILE

Soll: Alle eingetragenen Zeilen. Danach Ctrl+R drücken — die Suchmaske muss erscheinen.

Stimmt nicht

Fehler beim Start des Terminals? Die letzte eingefügte Zeile ist meist schuld. Profil öffnen, Zeile auskommentieren, Terminal neu starten:

PowerShell
notepad $PROFILE

Je Projekt

7 Schritte
Pro Projekt

Projekt anlegen oder klonen

Beim Klonen die SSH-Adresse verwenden, nicht HTTPS — dann greift der eingerichtete Schlüssel.

PowerShell
gh repo clone cloud7too9/MeinProjekt
# oder neu:
git init
git branch -M main
Prüfen
PowerShell
git remote -v

Soll: Eine Adresse mit git@github.com, nicht mit https://.

Stimmt nicht

Steht dort https, die Adresse umstellen:

PowerShell
git remote set-url origin git@github.com:cloud7too9/MeinProjekt.git
Pro Projekt

.editorconfig ins Wurzelverzeichnis

Gilt für alle Dateitypen und alle Editoren — auch dort, wo Prettier nicht greift.

.editorconfig
root = true

[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 2
insert_final_newline = true
trim_trailing_whitespace = true

[*.md]
trim_trailing_whitespace = false
Prüfen
PowerShell
git status

Soll: Die neue Datei taucht als unversionierte Änderung auf.

Stimmt nicht

Nicht sichtbar? Sie liegt im falschen Ordner. Die Datei muss neben der .git-Ordnerstruktur liegen:

PowerShell
dir -Force
Pro Projekt

Node-Version festschreiben

Damit alle, die das Repo klonen, dieselbe Version bekommen — und fnm beim Betreten automatisch umschaltet.

PowerShell
node -v > .nvmrc
Prüfen
PowerShell
Get-Content .nvmrc

Soll: Eine Versionszeile wie v20.11.1.

Stimmt nicht

Enthält die Datei Sonderzeichen, hat PowerShell UTF-16 geschrieben. Neu erzeugen:

PowerShell
node -v | Out-File -Encoding ascii .nvmrc
Pro Projekt

Prettier und ESLint aufnehmen

Als Entwicklungsabhängigkeiten ins Projekt, damit die Version im Repo festgeschrieben ist.

PowerShell
pnpm add -D prettier eslint
.prettierrc
{
  "semi": true,
  "singleQuote": true,
  "printWidth": 100
}
Prüfen
PowerShell
pnpm exec prettier --check .

Soll: „All matching files use Prettier code style!" oder eine Liste abweichender Dateien.

Stimmt nicht

Meldet es alle Dateien als abweichend, einmal komplett durchformatieren und den Stand committen:

PowerShell
pnpm exec prettier --write .
Pro Projekt

justfile anlegen

Die wiederkehrenden Projektbefehle an einen Ort, versioniert neben dem Code.

justfile
dev:
    pnpm run dev

bauen:
    pnpm run build

pruefen:
    pnpm exec eslint .
    pnpm exec prettier --check .

veroeffentlichen: bauen
    netlify deploy --prod
Hinweis
Anders als bei make sind Leerzeichen zur Einrückung erlaubt. Der Name hinter dem Doppelpunkt ist eine Abhängigkeit, die vorher läuft.
Prüfen
PowerShell
just --list

Soll: Alle Rezepte mit Namen.

Stimmt nicht

„No justfile found": Die Datei heißt exakt justfile, ohne Endung, und liegt im Wurzelverzeichnis:

PowerShell
dir justfile
Pro Projekt

CI-Workflow einrichten

Datei .github/workflows/ci.yml anlegen. Läuft ab dem nächsten Push automatisch.

.github/workflows/ci.yml
name: CI
on:
  push:
    branches: [main]
  pull_request:
jobs:
  bauen:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm
      - run: corepack enable
      - run: pnpm install --frozen-lockfile
      - run: pnpm run build
Nicht weitergeben
Zugangsdaten niemals in die YAML schreiben. Immer als Secret hinterlegen: gh secret set NAME
Prüfen
PowerShell
git push
gh run list --limit 1

Soll: Der neueste Lauf steht auf completed / success.

Stimmt nicht

Bei failure die Ursache direkt im Terminal ansehen:

PowerShell
gh run view --log-failed
Pro Projekt

Ersten Stand sichern

Alles Eingerichtete in einen Commit und hochladen.

PowerShell
git add .
git commit -m "Projektgrundlage eingerichtet"
git push -u origin main
Prüfen
PowerShell
git log --oneline -1
git status

Soll: Der Commit erscheint, und der Arbeitsbaum ist sauber.

Stimmt nicht

„src refspec main does not match any": Es gibt noch keinen Commit auf main. Branch umbenennen und erneut pushen:

PowerShell
git branch -M main
git push -u origin main
