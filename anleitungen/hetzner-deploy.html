Automatisches Deploy auf Hetzner per GitHub Actions

⏱ ca. 20 Min Aktualisiert 02.08.2026 Server Hetzner CX

Schritt-für-Schritt, wie ein Push auf main automatisch auf deinen Server ausrollt — sicher konfiguriert mit einem separaten Deploy-Key.

1

SSH-Schlüsselpaar generieren

Erstelle einen Schlüssel, der ausschließlich für dieses Deployment gedacht ist. Setze keine Passphrase — GitHub kann den Vorgang sonst nicht automatisieren.

Sicherheit
Nie deinen privaten Alltags-Key wiederverwenden. Ein eigener Key pro Zweck lässt sich jederzeit einzeln zurückziehen.
Terminal (lokal)
# Ed25519-Key ohne Passphrase, eigener Dateiname
ssh-keygen -t ed25519 -C "github-deploy" -f ~/.ssh/github_deploy_key -N ""
Ergebnis
Zwei Dateien entstehen: github_deploy_key (privat → kommt zu GitHub) und github_deploy_key.pub (öffentlich → kommt auf den Server).
2

Öffentlichen Schlüssel auf dem Hetzner-Server hinterlegen

Zeige den öffentlichen Schlüssel an, kopiere ihn und trage ihn auf dem Server in die authorized_keys deines Deploy-Benutzers ein.

Terminal (lokal)
# Öffentlichen Schlüssel anzeigen und kopieren
cat ~/.ssh/github_deploy_key.pub
Server (per SSH)
# Inhalt der .pub-Datei ans Ende anhängen
echo "<dein-öffentlicher-Schlüssel>" >> ~/.ssh/authorized_keys
3

GitHub Secrets konfigurieren

Im Repository unter Settings → Secrets and variables → Actions auf New repository secret. Lege drei Secrets an:

  • SERVER_HOST — IP-Adresse deines Hetzner-Servers
  • SERVER_USERNAME — Benutzername auf dem Server (z. B. deploy)
  • SSH_PRIVATE_KEY — kompletter Inhalt von github_deploy_key, inkl. der BEGIN/END-Zeilen
Terminal (lokal)
# Privaten Schlüssel vollständig anzeigen (für SSH_PRIVATE_KEY)
cat ~/.ssh/github_deploy_key
Privat halten
Der private Schlüssel gehört nur in das GitHub-Secret — niemals ins Repo committen oder weitergeben.
4

GitHub-Actions-Workflow erstellen

Lege im Repo die Datei .github/workflows/deploy.yml an. Bei jedem Push auf main startet die Action und rollt aus.

.github/workflows/deploy.yml
name: Deploy
on:
  push:
    branches: [ main ]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Per SSH ausrollen
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USERNAME }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            cd /var/www/mein-projekt
            git pull origin main
Vorab-Check auf dem Server
Damit git pull funktioniert, muss das Repo einmalig manuell in den Zielordner (z. B. /var/www/mein-projekt) geklont sein.
