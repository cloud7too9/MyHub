GitPflicht Versionsverwaltung — das Rückgrat von allem anderen.

Jedes weitere Werkzeug hier dockt an Git an: CI/CD löst bei Push aus, Deployments hängen an Commits, Code-Reviews an Branches. Ohne sauberes Git bleibt der Rest Stückwerk.

  1. Installieren
    winget install --id Git.Git -e
  2. Identität setzen — steht in jedem Commit
    git config --global user.name "Vorname Nachname"
                git config --global user.email "mail@beispiel.de"
  3. Sinnvolle Grundeinstellungen
    git config --global init.defaultBranch main
                git config --global pull.rebase true
                git config --global core.autocrlf true

    autocrlf true verhindert, dass Windows-Zeilenenden als Änderung an jeder Datei auftauchen.

  4. Erstes Repository anlegen
    git init
                git add .
                git commit -m "Erster Stand"
Prüfen
Steht es?
git --version
                git config --global --list

Versionsnummer plus deine Einträge für user.name und user.email.

Eingerichtet
OpenSSH & SchlüsselPflicht Zugang zu Servern und Git-Fernzugriff ohne Passworteingabe.

Sobald ein eigener Server im Spiel ist, läuft alles darüber: Deployment, Wartung, Dateitransfer. Ein sauberer Schlüssel plus config-Datei erspart täglich Tipparbeit.

  1. Schlüsselpaar erzeugen (ed25519, aktueller Standard)
    ssh-keygen -t ed25519 -C "max@arbeitsrechner"

    Eine Passphrase vergeben. Der Dateiname bleibt Standard, dann finden ihn alle Werkzeuge automatisch.

  2. Öffentlichen Schlüssel auf den Server bringen
    type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh nutzer@server "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
  3. Kurznamen in ~/.ssh/config anlegen
    Host mein-server
                  HostName 203.0.113.10
                  User max
                  IdentityFile ~/.ssh/id_ed25519

    Danach genügt: ssh mein-server

  4. Öffentlichen Schlüssel bei GitHub hinterlegen
    gh ssh-key add $env:USERPROFILE\.ssh\id_ed25519.pub --title "Arbeitsrechner"

  5. Passwort-Anmeldung am Server abschalten

    Achtung
    Erst prüfen, dass die Anmeldung per Schlüssel funktioniert — sonst sperrst du dich aus. Der private Schlüssel (ohne .pub) verlässt niemals den Rechner und gehört nie in ein Repository.
Prüfen
Steht es?
ssh mein-server "echo verbunden"
                ssh -T git@github.com

"verbunden" und eine Begrüßung von GitHub mit deinem Benutzernamen.

Caddyauf dem Server Reverse Proxy mit automatischem HTTPS-Zertifikat.

Nimmt Domain, Zertifikat und Weiterleitung an die Anwendung in drei Zeilen ab. Was bei nginx eine halbe Konfigurationsdatei ist, ist hier ein Block.

  1. Auf dem Server installieren

  2. /etc/caddy/Caddyfile schreiben

                }
  3. Übernehmen
    sudo systemctl reload caddy
  4. Ports freigeben
    sudo ufw allow 80,443/tcp

    Ohne offene Ports 80 und 443 kann Caddy kein Zertifikat ausstellen lassen.
